# CoreProtect Map Visualizer

Вебкарта для адміністраторів Minecraft-сервера, яка візуалізує події з бази даних [CoreProtect](https://www.spigotmc.org/resources/coreprotect.8631/): встановлення та руйнування блоків, дії з контейнерами й предметами, вбивства сутностей та інші події.

Дані відображаються поверх пласкої карти світу у вигляді кольорових точок і чанків. Доступні фільтри за гравцями, матеріалами, діями, часом, координатами та областю. Як фонову карту можна підключити наявний сервер BlueMap.

> [!IMPORTANT]
> Проєкт читає вихідну базу CoreProtect безпосередньо та відкриває її виключно в режимі **read-only**. Він не копіює та не змінює дані Minecraft-сервера.

## Можливості

- візуалізація подій CoreProtect на інтерактивній WebGL-карті;
- фільтрування за гравцями, матеріалами, діями, часом і координатами;
- огляд великих вибірок за чанками з подальшим завантаженням деталей;
- перегляд окремої події та сусідньої активності гравця;
- ручний запуск сканування без автоматичного навантаження на SQLite;
- опціональна растрова підкладка BlueMap;
- вхід за електронною поштою та паролем.

## Вимоги

Для встановлення та запуску потрібні:

- **Linux**;
- **Node.js 20 або новіший** (рекомендовано актуальну LTS-версію);
- **npm**, що постачається разом із Node.js;
- **Git** для клонування репозиторію;
- наявна SQLite-база плагіна CoreProtect (`database.db`) із правами на читання;
- **Caddy** для публічного доступу через HTTPS;
- опціонально — запущений сервер **BlueMap**, якщо потрібна фонова карта.

Backend використовує нативні модулі `better-sqlite3` і `argon2`. Зазвичай npm автоматично встановлює готові збірки. Якщо для вашої версії Node.js їх немає, додатково можуть знадобитися Python і системні засоби компіляції C/C++.

## Встановлення з GitHub

1. Клонуйте репозиторій і перейдіть до його каталогу:

   ```bash
   git clone https://github.com/ruslent2/CoreProtect-Map-Visualizer.git
   cd CoreProtect-Map-Visualizer
   ```

2. Встановіть залежності backend і frontend:

   ```bash
   npm run install:all
   ```

3. Створіть локальну конфігурацію з прикладу:

   ```bash
   cp config.example.json config.json
   ```

4. Відкрийте `config.json` і налаштуйте адресу сайту, CoreProtect DB та базу авторизації:

   ```json
    {
       "databasePath": "/path/to/CoreProtect/database.db",
       "port": 3010,
       "host": "127.0.0.1",
       "publicOrigin": "https://map.example.com",
       "auth": {
          "databasePath": "/opt/coreprotect-map-visualizer/data/auth.db",
          "sessionMaxAgeDays": 90,
          "sessionRenewAfterDays": 7,
          "secureCookies": true
       }
    }
   ```

    Використовуйте абсолютні шляхи. Процес застосунку повинен мати доступ до каталогу `auth.db` на читання та запис. База створюється автоматично під час першого запуску.

5. Якщо BlueMap не використовується, задайте:

   ```json
   {
     "bluemap": {
       "enabled": false
     }
   }
   ```

   Якщо BlueMap потрібен, збережіть решту параметрів із `config.example.json` і замініть `bluemap.baseUrl` адресою свого BlueMap-сервера.

6. Створіть першого користувача-адміністратора:

   ```bash
   npm --prefix server run auth:create
   ```

   Укажіть електронну пошту та двічі введіть пароль в інтерактивному режимі. Пароль не відображається та не передається через аргументи командного рядка.

`config.json`, локальні бази даних, каталог `data/` і зібраний frontend виключені з Git та не повинні публікуватися.

## Запуск

### Публічний запуск через HTTPS

Fastify повинен прослуховувати лише `127.0.0.1`. Не відкривайте його порт у зовнішню мережу. Публічні запити приймає Caddy та передає застосунку через localhost.

Приклад `Caddyfile`:

```caddyfile
map.example.com {
   reverse_proxy 127.0.0.1:3010
}
```

У `config.json` вкажіть той самий origin і ввімкніть захищені cookie:

```json
{
   "host": "127.0.0.1",
   "publicOrigin": "https://map.example.com",
   "auth": {
      "secureCookies": true
   }
}
```

Після запуску застосунку та Caddy відкрийте `https://map.example.com` і ввійдіть за допомогою облікового запису, створеного через CLI. Публічними повинні залишатися лише порти `80` і `443`.

### Єдиний сервер

Цей варіант збирає frontend і запускає Fastify, який обслуговує сайт та API на одному порту.

1. Зберіть frontend із кореня проєкту:

   ```bash
   npm run build:web
   ```

2. Запустіть сервер:

   ```bash
   npm run server
   ```

3. Для локальної перевірки відкрийте адресу Fastify. За замовчуванням:

   <http://127.0.0.1:3010>

   Для локального HTTP встановіть `auth.secureCookies: false`. Не використовуйте це значення на публічному сервері.

### Режим розробки

Запустіть backend і Vite у двох окремих терміналах:

```bash
npm run dev:server
```

```bash
npm run dev:web
```

Потім відкрийте <http://127.0.0.1:5173>. Vite автоматично проксіює запити `/api` до backend за адресою `127.0.0.1:3010`.

## Перевірка проєкту

```bash

```

Тести frontend:

```bash

```

Збірка frontend:

```bash
npm run build:web
```
