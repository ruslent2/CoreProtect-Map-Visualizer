# CoreProtect Map Visualizer

Веб-карта для администраторов Minecraft-сервера, которая визуализирует события из базы данных [CoreProtect](https://www.spigotmc.org/resources/coreprotect.8631/): установку и разрушение блоков, действия с контейнерами и предметами, убийства сущностей и другие события.

Данные отображаются поверх плоской карты мира в виде цветных точек и чанков. Доступны фильтры по игрокам, материалам, действиям, времени, координатам и области. В качестве фоновой карты можно подключить существующий сервер BlueMap.

> [!IMPORTANT]
> Проект читает исходную базу CoreProtect напрямую и открывает её строго в режиме **read-only**. Он не копирует и не изменяет данные Minecraft-сервера.

## Возможности

- визуализация событий CoreProtect на интерактивной WebGL-карте;
- фильтрация по игрокам, материалам, действиям, времени и координатам;
- обзор больших выборок по чанкам с последующей загрузкой деталей;
- просмотр отдельного события и соседней активности игрока;
- ручной запуск сканирования без автоматической нагрузки на SQLite;
- опциональная растровая подложка BlueMap;
- вход по email и паролю.

## Требования

Для установки и запуска потребуются:

- **Linux**;
- **Node.js 20 или новее** (рекомендуется актуальная LTS-версия);
- **npm**, поставляемый вместе с Node.js;
- **Git** для клонирования репозитория;
- существующая SQLite-база плагина CoreProtect (`database.db`) с правами на чтение;
- **Caddy** для публичного HTTPS-доступа;
- опционально — работающий сервер **BlueMap**, если нужна фоновая карта.

Backend использует нативные модули `better-sqlite3` и `argon2`. Обычно npm устанавливает готовые сборки автоматически. Если для вашей версии Node.js их нет, могут дополнительно потребоваться Python и системные инструменты компиляции C/C++.

## Установка из GitHub

1. Клонируйте репозиторий и перейдите в его каталог:

   ```bash
   git clone https://github.com/ruslent2/CoreProtect-Map-Visualizer.git
   cd CoreProtect-Map-Visualizer
   ```

2. Установите зависимости backend и frontend:

   ```bash
   npm run install:all
   ```

3. Создайте локальную конфигурацию из примера:

   ```bash
   cp config.example.json config.json
   ```

4. Откройте `config.json` и настройте адрес сайта, CoreProtect DB и базу авторизации:

   ```json
   {
       "databasePath": "/path/to/CoreProtect/database.db",
     "port": 3010,
       "host": "127.0.0.1",
       "publicOrigin": "https://map.example.com",
       "auth": {
          "databasePath": "/opt/coreprotect-map-visualizer/data/auth.db",
          "sessionMaxAgeDays": 90,
          "sessionRenewAfterDays": 7,
          "secureCookies": true
       }
   }
   ```

    Используйте абсолютные пути. Каталог для `auth.db` должен быть доступен процессу приложения на чтение и запись. База создаётся автоматически при первом запуске.

5. Если BlueMap не используется, задайте:

   ```json
   {
     "bluemap": {
       "enabled": false
     }
   }
   ```

   Если BlueMap нужен, сохраните остальные параметры из `config.example.json` и замените `bluemap.baseUrl` адресом своего BlueMap-сервера.

6. Создайте первого пользователя-администратора:

   ```bash
   npm --prefix server run auth:create
   ```

   Укажите email и дважды введите пароль в интерактивном режиме. Пароль не отображается и не передаётся через аргументы командной строки.

`config.json`, локальные базы данных, каталог `data/` и собранный frontend исключены из Git и не должны публиковаться.

## Запуск

### Публичный запуск через HTTPS

Fastify должен слушать только `127.0.0.1`. Не открывайте его порт во внешнюю сеть. Публичные запросы принимает Caddy и передаёт приложению через localhost.

Пример `Caddyfile`:

```caddyfile
map.example.com {
   reverse_proxy 127.0.0.1:3010
}
```

В `config.json` укажите тот же origin и включите защищённые cookie:

```json
{
   "host": "127.0.0.1",
   "publicOrigin": "https://map.example.com",
   "auth": {
      "secureCookies": true
   }
}
```

После запуска приложения и Caddy откройте `https://map.example.com` и войдите с учётной записью, созданной через CLI. Публичными должны оставаться только порты `80` и `443`.

### Единый сервер

Этот вариант собирает frontend и запускает Fastify, который обслуживает сайт и API на одном порту.

1. Соберите frontend из корня проекта:

   ```bash
   npm run build:web
   ```

2. Запустите сервер:

   ```bash
   npm run server
   ```

3. Для локальной проверки откройте адрес Fastify. По умолчанию:

   <http://127.0.0.1:3010>

    Для локального HTTP установите `auth.secureCookies: false`. Не используйте это значение на публичном сервере.

### Режим разработки

Запустите backend и Vite в двух отдельных терминалах:

```bash
npm run dev:server
```

```bash
npm run dev:web
```

Затем откройте <http://127.0.0.1:5173>. Vite автоматически проксирует запросы `/api` на backend по адресу `127.0.0.1:3010`.
